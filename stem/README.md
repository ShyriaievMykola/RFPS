# ЕнергоМонітор

Клієнтська частина системи моніторингу та прогнозування енергоспоживання багатоквартирного будинку.
STEM-проєкт з ОК «Розробник фронтенду програмних систем».

Мешканець бачить споживання своєї квартири, прогноз рахунку до кінця місяця, графік відключень
і власні ліміти. Адміністратор ОСББ бачить стан електроживлення будинку, спільних споживачів,
квартири та публікує оголошення.

## Запуск

Потрібен Node.js 20 або новіший.

```bash
npm install
npm run dev
```

Застосунок відкриється на `http://localhost:5173`.

Справжнього бекенду немає: запити до `/api/*` перехоплює мок-сервер (MSW) просто в браузері.
Дані зберігаються в `localStorage`, тож створені ліміти й оголошення переживають перезавантаження.
Щоб почати з чистого аркуша, очистіть дані сайту в браузері.

### Демо-доступ

На сторінці входу є кнопки «Мешканець» і «Адміністратор», які підставляють тестові облікові записи.
Самі записи та код запрошення для перевірки реєстрації лежать у [`src/mocks/seed.ts`](src/mocks/seed.ts).

## Команди

| Команда            | Що робить                                          |
| ------------------ | -------------------------------------------------- |
| `npm run dev`      | сервер розробки з гарячим перезавантаженням        |
| `npm run build`    | перевірка типів і production-збірка в `dist/`      |

Перед першим запуском наскрізних тестів потрібно один раз завантажити браузери:

```bash
npx playwright install chromium firefox webkit
```

## Структура

```
src/
  app/          каркас: маршрути, захист маршрутів, оболонка з меню
  features/     сторінки за розділами (auth, dashboard, analytics, outages,
                limits, reports, admin, settings, notifications, power)
  shared/
    api/        типи контракту з сервером, HTTP-клієнт, хуки запитів
    lib/        чиста логіка: прогноз, тарифи, CSV, форматування, схеми валідації
    ui/         перевикористовувані компоненти та графіки
    stores/     сховища стану (сесія, налаштування)
    i18n/       переклади
  mocks/        мок-сервер: генератор даних, «база», обробники запитів
e2e/            наскрізні тести
```

## Як рахується прогноз

Логіка в [`src/shared/lib/forecast.ts`](src/shared/lib/forecast.ts).

1. Береться добове споживання за останні 8 тижнів.
2. Воно згладжується експоненційно (коефіцієнт 0,3), окремо для буднів і вихідних.
3. Прогноз на місяць дорівнює вже спожитому плюс очікуване споживання за дні, що залишились.
4. 80-відсотковий інтервал будується з похибки моделі на минулих даних.

## Вимоги до проєкту

**Адаптивність.** Верстка від мобільної: на телефоні меню стає нижньою панеллю вкладок, таблиці
прокручуються всередині картки. Наскрізні тести перевіряють відсутність горизонтального прокручування.

**Кросбраузерність.** Наскрізні тести запускаються в Chromium, Firefox, WebKit і на мобільному екрані.
Перелік цільових браузерів задано полем `browserslist` у `package.json`.

**Захищеність.**

- Access-токен зберігається лише в пам'яті вкладки; сесію відновлює окремий запит.
- Роль перевіряє сервер у кожному запиті; приховане меню на клієнті захистом не вважається.
- Після п'яти невдалих спроб вхід блокується на 30 секунд.
- Відповіді про хибний пароль і неіснуючу адресу однакові, тож перелік користувачів не розкривається.
- HTML оголошень очищається DOMPurify перед показом.
- Production-збірка містить Content Security Policy (див. `vite.config.ts`).
- Усі форми перевіряються схемами Zod і на клієнті, і на мок-сервері.
- Клітинки CSV, що починаються з `=`, `+`, `-`, `@`, екрануються від виконання як формул.

**Зручність.** Скелетони під час завантаження, порожні стани й стани помилок із кнопкою повтору,
спливні сповіщення, світла й темна теми, керування з клавіатури, підписи для екранних дикторів,
табличний вигляд для кожного графіка.

## Обмеження

- Бекенд імітований. У мок-сервері refresh-токен зберігається в `localStorage`, бо Service Worker
  не може виставити httpOnly-cookie; у справжній системі це була б саме така cookie.
- Дані лічильників генеруються детерміновано з номера квартири й часу, а не надходять з обладнання.
- Скидання пароля лише показує підтвердження: лист не надсилається.
